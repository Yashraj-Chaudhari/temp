A · Overview

What is this project?

Plant phenotyping measures plant traits and condition. This project explores pixel-level weed segmentation from aerial imagery, plus separate map and flight-control prototypes.

30-second answer

“This project explores weed detection in aerial imagery with semantic segmentation. It has PyTorch model definitions and notebook experiments, plus separate prescription-map and waypoint prototypes. I cannot reproduce a complete flight-to-spray system from this checkout: data/checkpoints are absent, training depends on missing modules and machine-specific paths, and map, route and controller code have no verified handoff. The strongest defensible contribution here is exploratory segmentation code and related prototypes.”

Two-minute answer

Segmentation assigns a class to each pixel, which can show where weeds occupy an image. The repo has DeepLab-style and U-Net source plus notebook code for images, masks, training and visualizations. It computes ExG/ExGR/CIVE-like values from RGB; those are derived features, not extra sensor bands.

Separate map experiments calculate patch statistics, path examples use in-memory grids, and ROS/MAVROS code publishes fixed XYZ positions. These are not joined into a verified spraying system.

Why segmentation?

A whole-image label cannot show weed location. A pixel mask can support spatial summaries; it does not identify plant instances, calibrate physical area, decide dose, or operate a sprayer.

RGB-derived expressions

ExG = 2G − R − B
ExGR = ExG − (1.4R − G)
CIVE = .441R − .811G + .385B + 18.78745

Three computed RGB channels, not NIR/CIR. Float32, no /255 in shown transform. README describes six bands, so source/document mismatch needs resolution.

Mask semantics

Weed/background names, palettes, RGB/BGR conversions and polarity vary across cells. Confirm color→class→weed mapping before interpreting area. Test data must not fit/tune model.

Explain like I am new to this

RGB stores three colors per pixel. Segmentation chooses a class per pixel. An index is math on sensor bands, not an extra sensor.

I · Path and drone

A route is not spraying

Path notebook

Greedy, graph/TSP-like and lawnmower sketches use random/in-memory grids. Score/distance units are not normalized; no map-file reader.

Controller

Fixed targets: (0,0,2.5), then y=2,4,6,8,10. Waits MAVROS, sends at 20Hz, requests OFFBOARD/arm, component-wise tolerance .1. The waypoint duration check uses the shared last_req timer also used for OFFBOARD/arm requests, rather than a per-waypoint arrival timer. Publishes one-pose Path each loop. No map, spray, landing or clear failsafe.

Camera and evidence

camera.py previews device 9 only. README claims SITL; repeatable launch evidence is absent. A controller file does not prove flight. Field spraying is not established.

Honest defense: intended offboard setpoint loop; no demonstrated model targeting, autonomous spraying or real flight.

L · Paper context

Broader publication versus checkout

README cites Pandey, Borade, Sharma & Kannaiyan, “Agricultural Assessment Using Aerial-Imagery Data with Deep Convolution Network and Prescription Map Algorithm for Optimized Spraying Path,” International Journal of Applied Mathematics 38(7s), 488–504 (2025), DOI 10.12732/ijam.v38i7s.496. I accessed the publisher’s 17-page PDF.

The paper describes WeedMap and CoFly-WeedDB plus Indian field data, states RGB was used for WeedMap despite additional aligned channels, describes georeferencing, image stitching, filtering and patch density D=W/T, and discusses lawnmower, priority-based and TSP routes. Its abstract reports 92.22% RGB and 95.04% transformed-input accuracy. The paper defines patch density as D=W/T (weed pixels divided by total pixels); hypothetically, 1,600/6,400=.25. This worked example is illustrative, not measured. These are publication claims, not results reproduced from this checkout. The local code has RGB-derived index expressions, but its checked-in DeepLab uses ResNet101 while the paper describes ResNet50; the paper’s broader integration and processing steps are not fully implemented in the inspected repository. The README attributes thesis work to VNIT 2023–24 and identifies Yuvraj Borade as a paper co-author; that does not establish the presenter’s personal contribution.
